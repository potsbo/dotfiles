# キーバインド仕様

## この文書の位置づけ

**物理キーを押したら何が起きるか**を OS 非依存で定義する。仕様だけを書く。
どの設定ファイルでどう実現しているか、今どこまで実装できているかは書かない
(それは各設定ファイルの直上コメントの担当)。

実装が仕様を満たせないときは、仕様を直すか「OS で概念が違うので揃えない」と §4 に
書く。実装の都合で仕様を暗黙に変えない。

1 つの設定ファイルの直上に置けないのでこのファイルがある。複数のレイヤにまたがる
仕様だから。

**設定より先にここを直す。** キーバインドを変えるときの手順は CLAUDE.md にある。

## 1. 基準の盤: HHKB Studio

MacBook 内蔵キーボードは「HHKB のこのキーに相当するのはこれ」という写像で扱う。
仕様の言語は HHKB Studio の物理配列。

### 1.1 修飾キーの役割名

物理位置で呼ぶ。以降この名前だけを使う。

| 役割名  | HHKB Studio の物理位置 | MacBook 内蔵での相当 |
| ------- | ---------------------- | -------------------- |
| `⌘`     | スペースの左右の隣     | ⌘ キー               |
| `⌥`     | `⌘` の 1 つ外側        | option キー          |
| `Ctrl`  | A の左                 | CapsLock の位置      |
| `Shift` | 通常位置               | 同じ                 |
| `Fn`    | 右下                   | fn キー              |

### 1.2 前提: 矢印キーは Fn レイヤにしかない

HHKB Studio に独立した矢印キーは無い。したがって「修飾キー + 矢印」は実質
3〜4 キー同時押しになる。

**矢印を一級市民にしない。** 矢印を使うバインドは MacBook 内蔵キーボード向けの
別名として扱い、HHKB だけで完結する経路を必ず併設する。

例外は、他に適切なバインドが見つからないときだけ。今のところ E9〜E12 (単語・段落の
移動と選択) と P1 / P2 (左右半分) がこれに当たる。押しにくさは受け入れる。

### 1.3 単押しの二重用途

修飾キーを単独で叩いたときに別のものを送る。押しっぱなしなら本来の修飾キーとして
働く。

| ID  | 物理キー          | 起きること         |
| --- | ----------------- | ------------------ |
| S1  | 左 `Ctrl` 単押し  | Esc                |
| S2  | 左 `⌘` 単押し     | 日本語入力を英数へ |
| S3  | 右 `⌘` 単押し     | 日本語入力をかなへ |
| S4  | 右 `Shift` 単押し | ランチャーを開く   |

## 2. 修飾キーの役割分担

仕様の背骨。ここが決まっていれば、新しい機能をどのキーに置くかは自動的に決まる。

| 修飾     | 担当する領域                | なぜ                                             |
| -------- | --------------------------- | ------------------------------------------------ |
| `⌘`      | アプリの操作                | macOS の筋肉記憶をそのまま持ち込むのが全体の目的 |
| `Ctrl`   | 行内編集と端末              | Emacs 風のカーソル移動と、端末の中断・終了       |
| `⌥`      | 単語単位の編集。アプリに渡す | 下記のとおり、ここは奪えない                     |
| `Ctrl+⌥` | 画面内の位置決め (格子配置) | Magnet の既定がここで、長年の筋肉記憶がある      |
| `⌘+⌥`    | ウィンドウマネージャ        | 修飾キー 1 つの面はどれも埋まっている            |

Tab はこの役割分担がそのまま出た形にする。**`⌘`+Tab でアプリを特定し、`⌥`+Tab で
その中のウィンドウを特定する** (A3 と W2)。アプリ単位で直近順に切り替える仕組みを
持たない環境ではウィンドウ単位に落ちてもよいが、あくまでアプリ単位を原則とし、
メンタルモデルとしてはこの二段構えを崩さない。

**`⌥` 面は奪わない。** 単語単位の移動・削除・大文字化、直前の引数の挿入、履歴検索と
いった編集操作が `⌥`+英字 と `⌥`+矢印 に一通り載っている (E9〜E12 はそのうち
どのアプリでも効くもの)。`Ctrl` 面の行内編集と同じくらい使うので、ここをウィンドウ
マネージャが取ると端末でもエディタでも編集操作が丸ごと消える。

2026-09-13 に一度 `⌥` をウィンドウマネージャに充てたが、上の理由で取りやめた。
ウィンドウマネージャは `⌘+⌥` に置く。修飾キー 1 つで空いている面はもう無い。

ただし **`⌘+⌥` も面ごと取るのではなく、必要なキーだけ取る**。ここは空き地ではない。
アプリが使う組み合わせ (`⌘⌥I` の開発者ツール、`⌘⌥←/→` のタブ切り替え、`⌘⌥Esc` の
強制終了など) は避ける。`⌥` 面ほど密ではないので、避けて置ける。

例外は `⌥`+Tab (W2)。Tab は編集操作に使われていないので取ってよい。

## 3. 機能一覧

### 3.1 編集・入力 (アプリ非依存)

| ID  | 物理キー                     | 起きること                |
| --- | ---------------------------- | ------------------------- |
| E1  | `Ctrl`+A / E                 | 行頭 / 行末へ             |
| E2  | `Ctrl`+F / B                 | 1 文字進む / 戻る         |
| E3  | `Ctrl`+N / P                 | 1 行下 / 上へ             |
| E4  | `Ctrl`+D / H                 | 前方削除 / 後方削除       |
| E5  | `Ctrl`+K                     | 行末まで削除              |
| E6  | `Ctrl`+M                     | 確定 (Enter)              |
| E7  | 端末では E1〜E6 を変換しない | `Ctrl`+C が中断として届く |
| E8  | 英字・記号の配置             | Anpan 配列                |
| E9  | `⌥`+← / →                    | 単語単位で移動            |
| E10 | `⌥`+`Shift`+← / →            | 単語単位で選択            |
| E11 | `⌥`+Delete                   | 前の単語を削除            |
| E12 | `⌥`+↑ / ↓                    | 段落単位で移動            |

### 3.2 アプリ操作 (`⌘`)

| ID  | 物理キー                                                      | 起きること                                |
| --- | ------------------------------------------------------------- | ----------------------------------------- |
| A1  | `⌘`+C / V / X / A / Z / S / W / T / F / R / L / N / O / P / Q | アプリの標準ショートカット                |
| A2  | 端末での `⌘`+C / V                                            | コピー / ペースト (中断にしない)          |
| A3  | `⌘`+Tab                                                       | 直近に使ったアプリへ (アプリ単位を原則とする) |
| A4  | ブラウザでの `⌘`+Q                                            | 全ウィンドウ・全タブを閉じる              |
| A5  | `⌘`+Enter                                                     | ページ内の確定 (クエリ実行、メール送信)   |

### 3.3 ウィンドウマネージャ (`⌘+⌥`)

| ID  | 物理キー      | 起きること                                   |
| --- | ------------- | -------------------------------------------- |
| W1  | `⌘`+W / `⌘`+Q | 窓を閉じる (A1 に含む)                       |
| W2  | `⌥`+Tab       | いま使っているアプリのウィンドウを切り替える |
| W3  | `⌘`+`⌥`+Tab   | Mission Control                              |

W2 だけ `⌥` 面にいるのは §2 の例外。

### 3.4 画面内の位置決め (`Ctrl+⌥`)

画面を左右半分 / 2x2 に見立てた枠に窓を置く。Magnet の配置。枠は**今見えている
作業領域**を基準にする。すでにその枠の側にいる窓は、その方向へは動かず、高さや幅
だけが変わる (一番左の窓に P3 なら、左右には動かず高さが半分になって上側に座る)。

| ID  | 物理キー         | 起きること                   |
| --- | ---------------- | ---------------------------- |
| P1  | `Ctrl`+`⌥`+←     | 窓を画面の左半分に置く       |
| P2  | `Ctrl`+`⌥`+→     | 窓を画面の右半分に置く       |
| P3  | `Ctrl`+`⌥`+U     | 窓を左上の 1/4 に置く        |
| P4  | `Ctrl`+`⌥`+I     | 窓を右上の 1/4 に置く        |
| P5  | `Ctrl`+`⌥`+J     | 窓を左下の 1/4 に置く        |
| P6  | `Ctrl`+`⌥`+K     | 窓を右下の 1/4 に置く        |
| P7  | `Ctrl`+`⌥`+Enter | 窓を作業領域いっぱいに広げる |

P3〜P7 は Fn が要らないが、P1 / P2 は HHKB では Fn も要るので 4 キー同時押しになる。
四隅の 2x2 の両脇にあたる `Ctrl`+`⌥`+H / L に移す案を検討したが、**H は空いていない**。
E4 で `Ctrl`+H を後方削除にしているので、`Ctrl`+`⌥`+H は `⌥`+BackSpace = 前の単語を
削除 (E11) と同じ打鍵になる。他に適切な代替が無いので矢印のままにする (§1.2 の例外)。

`Ctrl+⌥` に何か足すときは、`Ctrl`+英字 の編集操作 (§3.1) と重ならないか毎回確かめる。

## 4. OS で概念が違うので揃えないもの

同じ物理キーに同じ意図を割り当てられない領域。無理に揃えず、理由を書いて分ける。

### 4.1 格子配置 (§3.4) で隣の窓が追従するか

タイリングの環境では、枠に窓を置くと**空いた枠に隣の窓が入り、その窓を閉じると残りが
広がる**。窓どうしが場所を分け合う。

浮動の環境では枠に置いた窓どうしは無関係で、何も追従しない。空いた枠は空いたまま。

この差は許容する。どちらも「押した窓が指定の枠に来る」という点では同じで、違うのは
周りの窓だけだから。
